1. Operational Problem

Transit agencies publish schedule and network data in the General Transit Feed Specification (GTFS) as relational CSV/TXT tables. To evaluate pedestrian walk-sheds (e.g., 800m / 10-minute station catchments) or corridor service coverage, those tabular feeds must be joined, projected into a metric coordinate system, buffered, and exposed in a GIS or Web-GIS interface.

2. Data & Spatial Pipeline

  1. Feed Ingestion: Read stops.txt, routes.txt, and stop_times.txt using Python.
  2. Coordinate Projection: Convert WGS 84 (EPSG:4326) stop coordinates into Calgary's local metric projection (NAD83 / Alberta 3TM ref merid 114 W) for accurate 800m Euclidean or network-based buffering.
  3. GeoJSON Serialization: Re-project output polygons and corridor lines back to EPSG:4326 GeoJSON for browser-native rendering in Leaflet.

3. Code & Architecture

Example Python / SQL query pattern used to extract high-frequency stops and serialize them into a Web-GIS-ready GeoJSON FeatureCollection:

gtfs_to_geojson.py · Python 
import csv
import json

def stops_to_geojson(stops_txt_path: str, output_geojson_path: str) -> int:
    features = []
    with open(stops_txt_path, mode="r", encoding="utf-8-sig") as f:
        reader = csv.DictReader(f)
        for row in reader:
            lat = float(row["stop_lat"])
            lon = float(row["stop_lon"])
            features.append({
                "type": "Feature",
                "properties": {
                    "feature_type": "station",
                    "gtfs_stop_id": row["stop_id"],
                    "name": row["stop_name"]
                },
                "geometry": {
                    "type": "Point",
                    "coordinates": [lon, lat]
                }
            })

    collection = {"type": "FeatureCollection", "features": features}
    with open(output_geojson_path, mode="w", encoding="utf-8") as out:
        json.dump(collection, out, indent=2)
    return len(features)
